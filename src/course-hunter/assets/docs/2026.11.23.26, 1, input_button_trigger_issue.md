The cause is in `parseOrFetchAtom`. After a copied state is parsed, it calls `document.getElementById(CLEAR_BUTTON_ID)?.focus()`, which moves focus from the input to the Clear button. Pressing Enter again then activates the focused Clear button, so it clears the data. I'll remove that focus call so focus stays where the user is typing.

The Enter key was triggering Clear because of a focus change in the parse logic, not in the input component.

**Cause:** In `parseOrFetchAtom` (`src/course-hunter/store/a-actions.ts`), when the pasted text is a copied app state, the code parsed it and then called `document.getElementById(CLEAR_BUTTON_ID)?.focus()`. That moved focus from the input to the Clear button. The next Enter press activated the focused Clear button, which cleared the data. The Clear button has `tabIndex={-1}`, but `focus()` still works when called from code.

**Fix:** I removed the `focus()` call, so focus stays in the input. I also updated the `CLEAR_BUTTON_ID` doc comment, which described the removed behavior. `CLEAR_BUTTON_ID` is still used as the button's `id` in `1-row1-source-input.tsx`.

I haven't run the app to verify this. The trade-off is that the Clear button no longer receives focus after a state paste. If that focus was intentional, it would need a different trigger, for example only when the parse came from a button click rather than Enter.
